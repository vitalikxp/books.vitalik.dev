# DESIGN.md — «Моя библиотека»

Версия: **2.0**  
Дата: **9 октября 2026 года**  
Экран: **каталог домашней библиотеки**  
Темы: **светлая / тёмная**  
Язык интерфейса: **русский**, с поддержкой латиницы в названиях и ярлыках

## 1. Назначение и актуальные референсы

Документ задаёт общую визуальную систему каталога и два её цветовых варианта. Он предназначен для реализации интерфейса по последним светлому и тёмному макетам из этой беседы.

| Референс | Размер изображения | Что из него берём |
| --- | --- | --- |
| Светлый снимок сайта `image(4).png` | 1885 × 984 px | Состав экрана, порядок книг, надписи, исходный вид обложек, светлое оформление |
| Тёмный макет `exec-d2fe3f8d-c4d0-4e05-8df9-90cecd90816d.png` | 1736 × 906 px | Тёплую тёмную палитру, характер поверхностей, текста и зелёных акцентов |

Тёмное изображение имеет меньший масштаб. **Темы используют одну геометрию:** размеры компонентов нельзя уменьшать при переходе к тёмной теме вслед за размером растрового файла.

Пиксели изображений не содержат достоверных данных об исходных CSS и файлах шрифтов. Значения ниже нормализованы для реализации: размеры округлены, а контраст отдельных подписей и границ усилен. При расхождении пикселей с этой спецификацией приоритет имеют зафиксированные токены, читаемость и устойчивость компоновки.

**На обоих изображениях показаны:** левая панель «ЯРЛЫКИ», поиск, три варианта сортировки, четыре книги в одном ряду, авторы и тематические чипы. Один ряд отражает текущую демонстрационную коллекцию; каталог может содержать больше книг и рядов.

**Проектные дополнения этого документа:** переключатель темы, адаптивная компоновка, поведение поиска и ярлыков, hover/focus/pressed, загрузка, ошибки и пустые состояния. Эти состояния не следует считать уже нарисованными или реализованными на сайте.

Редакция 2.0 заменяет описание прежнего макета на восемь художественных книг. Учёт чтения, выдачи друзьям, комнат и физических полок, добавление книги и представление списком остаются за рамками текущего экрана. Их прежние токены и сценарии не определяют актуальный каталог.

## 2. Назначение продукта и визуальный характер

Каталог помогает просматривать домашнюю коллекцию, находить книгу по названию, автору или ISBN и сужать выдачу по тематическому ярлыку. Пользователь может менять порядок книг и открывать сведения о выбранной записи.

Основная единица интерфейса — запись каталога. Стратегия учёта нескольких экземпляров одного издания определяется данными продукта и здесь не задаётся.

**Характер:** спокойный, книжный, домашний, аккуратный. Обложки создают основное цветовое разнообразие. Элементы управления поддерживают чтение каталога и занимают умеренную площадь.

| Свойство | Светлая тема | Тёмная тема |
| --- | --- | --- |
| Общее ощущение | Тёплая бумага, спокойный дневной свет | Тёплый угольный фон с оливковым подтоном |
| Основной текст | Тёмный серо-зелёный | Мягкий молочный |
| Вторичный текст | Контрастный серо-оливковый | Светлый приглушённый серо-зелёный |
| Активное управление | Глубокий хвойный | Более светлый приглушённый зелёный |
| Обложки | Исходные цвета изданий | Те же исходные цвета изданий |

Фоны ровные. Обязательная бумажная текстура из прежней редакции отменена: для актуального экрана достаточно цвета. Не добавлять градиенты, виньетку, неоновое свечение или шум под текстом.

Карточка книги располагается непосредственно на фоне страницы. Тень и мягкий край принадлежат обложке; общая панель вокруг изображения, названия и ярлыков не нужна.

## 3. Компоновка большого экрана

### 3.1. Каркас

Слева находится постоянная боковая панель с вертикальным разделителем. Справа — основной контейнер каталога. Его содержимое центрируется в доступной области и ограничивается по ширине.

| Параметр | Значение для ширины от 1600 CSS px |
| --- | --- |
| Боковая панель | 310 px |
| Внутренний горизонтальный отступ панели | 24 px |
| Декоративный разделитель | 1 px |
| Максимальная ширина содержимого каталога | 1200 px, без внешних полей |
| Минимальные внешние поля основной области | 32 px с каждой стороны |
| Верхний отступ каталога | 32 px |
| Панель поиска и сортировки | Одна строка, высота 48 px |
| Интервал между поиском и сортировкой | 12 px |
| Панель управления → обложки | 44 px |
| Колонки книг | 4 равные колонки |
| Промежуток между колонками | 48 px |
| Промежуток между рядами | 40 px после самого высокого блока ряда |
| Нижнее поле страницы | Не менее 48 px |

При ширине содержимого 1200 px колонка равна 264 px. Обложка шириной до 220 px центрируется внутри колонки; текст начинается от левого края колонки, поэтому текстовый блок шире обложки. Такой ритм соответствует актуальным изображениям.

Фактические ориентиры светлого снимка — боковая панель около 310 px, начало содержимого около x = 482 px и верх обложек около y = 125 px. Эти координаты помогают сравнить композицию, но не должны превращаться в абсолютное позиционирование страницы.

Основная страница прокручивается по вертикали. Боковая панель закреплена в пределах окна и при нехватке высоты позволяет прокрутить своё содержимое. Нижняя настройка темы не перекрывает ярлыки. Высоту каталога определяют данные; свободное место под четырьмя книгами не заполняется декоративными блоками.

### 3.2. Порядок содержимого

1. В верхней строке — поиск; справа от него сортировка.
2. Ниже — сетка обложек с названиями, авторами и ярлыками.
3. В состояниях загрузки, ошибки или отсутствия результатов соответствующее сообщение занимает область сетки.

Видимый крупный заголовок над поиском в актуальном макете отсутствует. Для семантики страницы предусмотреть один визуально скрытый `h1` «Каталог книг», который остаётся доступным вспомогательным технологиям.

Зелёный выбранных элементов и границы управления в тёмной палитре немного светлее соответствующих пикселей макета. Это нормализация для читаемости и различимости состояния. Нейтральные декоративные линии могут оставаться мягкими.

Размеры текста задаются в `rem`. Для «ЯРЛЫКИ» используется `letter-spacing: 0.08em`; у остальных интерфейсных подписей — обычный межбуквенный интервал. Счётчики допускают табличные цифры, чтобы изменение числа не сдвигало правый край.

Название книги занимает до двух строк с визуальным многоточием. Полный текст остаётся в данных и в доступном имени ссылки. Автор в показанном состоянии занимает одну строку; длинные имена могут переноситься на вторую. Не уменьшать кегль ради размещения длинного названия и не заменять полные данные уже сокращённой строкой.

Для длинных названий, ISBN без пробелов и непрерывных латинских строк предусмотреть безопасный перенос внутри колонки. Использовать `min-width: 0` у элементов сетки. Полные сведения должны быть доступны при открытии записи и не зависеть от tooltip по наведению.

Загрузка шрифтов использует резервные семейства и `font-display: swap`. Перед выпуском проверить строку: «Моя библиотека · Ёё Йй Щщ Ъъ Ыы Ьь Ээ Юю Яя · Computer Science · ISBN 978-5-00000-000-0». Это проверка отображения, а не пример ISBN конкретной книги.

Надписи внутри обложек относятся к изображению издания. Они не набираются заново Lora или Inter.

## 7. Боковая панель и ярлыки

### 7.1. Состав актуального экрана

Верхняя группа содержит контурную иконку раскрытой книги размером 32 px и название «Моя библиотека». Отступ сверху — 24 px; промежуток между иконкой и текстом — 12 px. При ширине самой панели до 288 px использовать компактную комбинацию: надпись 22/28 px, иконка 28 px, промежуток 8 px и горизонтальные поля панели 20 px. Это правило действует и для постоянной, и для выдвижной панели; название помещается в одну строку.

Ниже располагается подпись «ЯРЛЫКИ» с маленькой контурной иконкой. Навигация использует такой порядок:

### 7.2. Поведение фильтра

Для текущей реализации выбран **один ярлык за раз**. Выбор другого заменяет предыдущее ограничение. «Все книги» снимает ограничение по ярлыку, сохраняя поисковый запрос и сортировку.

Поиск и выбранный ярлык применяются совместно. Например, поиск «Кори» внутри «Программирование» показывает соответствующие записи с этим ярлыком. Активный ярлык остаётся виден в панели и после обновления результатов.

Пункты навигации оформляются ссылками на состояние каталога; текущая ссылка получает `aria-current="page"`. При возврате со страницы книги восстанавливаются выбранный ярлык, поисковый запрос, сортировка и положение прокрутки каталога. Если проект использует другую маршрутизацию, программная семантика выбора должна оставаться однозначной.

Чипы под книгой в этой спецификации являются информационными метками. Они не входят в порядок Tab и не получают hover-оформление кнопки. Выбор фильтра выполняется в боковой панели. Такое поведение — проектное решение; интерактивность чипов нельзя определить по одному снимку.

### 7.3. Состояния навигации и выбора

| Состояние | Фон | Текст / иконки | Дополнительное обозначение |
| --- | --- | --- | --- |
| Обычный | Прозрачный | `--color-text` | Счётчик — `--color-muted` |
| Hover обычного | `--color-hover-surface` | `--color-text` | Геометрия сохраняется |
| Выбранный | `--color-primary` | `--color-on-primary` | Программное текущее состояние, насыщенность 500 |
| Hover выбранного | `--color-primary-hover` | `--color-on-primary` | Текущий выбор сохраняется |
| Pressed выбранного | `--color-primary-active` | `--color-on-primary` | Тонкий внутренний контур цветом `--color-on-primary` |

## 8. Поиск и сортировка

### 8.1. Поиск

Поле занимает свободное место в верхней строке. Сортировка имеет ширину по содержимому, ориентировочно 396 px. У поиска `min-width: 0`; при нехватке места управление перестраивается по разделу 11.

Высота поиска — 48 px, радиус — 8 px, фон — `--color-surface`, граница 1 px — `--color-control-border`. Внутри слева иконка 20 px, поле 16 px, промежуток до текста 12 px. Подсказка точно повторяет референс: **«Название, автор или ISBN»**.

Поиск имеет отдельную доступную подпись «Поиск по библиотеке»; placeholder её не заменяет. Форма размечается как область поиска. Иконка внутри подписанного поля декоративная.

Правила реализации:

- Искать по названию, автору и ISBN, если ISBN присутствует у записи. Отсутствие ISBN не исключает книгу из поиска по другим полям.
- Не учитывать регистр; при поисковом сравнении считать «е» и «ё» эквивалентными, сохраняя исходное написание в интерфейсе.
- Для сравнения ISBN игнорировать пробелы и дефисы. Это отдельная нормализация ISBN, а не удаление пробелов из всех текстовых запросов.
- Обновлять выдачу через 250 мс после последнего ввода; Enter применяет запрос сразу. Во время IME-композиции не отправлять незавершённый запрос.
- При заполненном поле показывать очистку с доступным названием «Очистить поиск» и областью нажатия 44 × 44 px. Очистка сохраняет ярлык и сортировку.
- Сохранять фокус в поле при изменении выдачи. Запоздавший ответ предыдущего запроса не должен заменять более свежий результат.
- После завершённого обновления объявлять количество результатов через `aria-live="polite"`, без озвучивания каждой буквы.

На пустом поле применяется цвет `--color-placeholder`; введённый текст использует `--color-text`. Фокус обозначается обводкой, а не только сменой цвета границы.

### 8.2. Сортировка

Три видимых сегмента — **«Недавно»**, **«По названию»**, **«По автору»**. У первого иконка часов, у остальных соответствующие контурные пиктограммы. Одновременно выбран ровно один вариант; начальное значение — «Недавно».

| Вариант | Значение | Правило |
| --- | --- | --- |
| Недавно | `recent` | Дата добавления по убыванию; записи без даты после записей с датой |
| По названию | `title` | По полному названию, в порядке русской локали с поддержкой латиницы |
| По автору | `author` | По сохранённому ключу автора «фамилия, имя», если он есть; иначе по полной подписи автора |

Фамилия не угадывается автоматически по последнему слову имени. Записи без автора располагаются в конце сортировки по автору. Для равных значений используются стабильные дополнительные ключи: название, затем идентификатор записи. Одинаковый запрос должен давать устойчивый порядок.

Переключение сортировки сохраняет поиск, ярлык и состав подходящих записей. Для буквенного сравнения выбрать локаль `ru` и не учитывать регистр; согласовать один порядок в клиентской и серверной реализации, если используются обе.

Контейнер сортировки имеет высоту 48 px, радиус 8 px, фон `--color-surface` и границу `--color-control-border`. При 1 px внешней границы и 1 px внутреннего поля сегмент сохраняет высоту 44 px. Между иконкой и текстом — 8 px. Внутренний радиус выбранного сегмента — 6 px.

Сегменты реализуются как одна радиогруппа с доступным названием «Сортировка книг». Tab переводит фокус в группу; стрелки выбирают вариант и меняют сортировку. Выбор передаётся состоянием radio, а его визуальная заливка использует правила раздела 7.3. Названия не заменяются одними иконками.

## 9. Карточка книги и изображения

### 9.1. Структура

| Порядок | Содержимое | Отступ после предыдущего элемента |
| --- | --- | --- |
| 1 | Обложка в общем слоте | — |
| 2 | Название, до двух строк | 12 px |
| 3 | Автор, обычно одна строка | 4 px |
| 4 | Информационные ярлыки с иконками | 8 px |

Для строки названий резервируется высота двух строк, чтобы авторы соседних карточек не поднимались под коротким заголовком. Длинный автор может увеличить карточку; высота ряда сетки определяется самым высоким содержимым. Чипы переносятся естественно, без ограничения двумя строками для будущих данных.

Обложка и название ведут к одной записи и образуют одну остановку клавиатурного фокуса. Полные название и автор доступны в подробных сведениях; отдельная композиция этого экрана здесь не задаётся.

На hover разрешены `--shadow-cover-hover` и подчёркивание названия. Подчёркивание повторяется при клавиатурном фокусе. Обложки и карточки сохраняют размеры и положение: без наклона, масштабирования и подъёма.

### 9.2. Обложки

Опорный слот — **220 × 312 px**, отношение сторон **55:78**, близкое к вытянутым обложкам актуального снимка. Предыдущее значение 4:5 больше не используется.

На более узкой колонке ширина слота уменьшается пропорционально. Ориентир — `min(220px, ширина колонки − 32px)`; на одноколоночном экране допустима ширина до 220 px без обязательных боковых отступов внутри карточки. Все слоты одного ряда имеют одинаковую высоту.

Изображение показывается через `object-fit: contain`, центрируется по горизонтали и выравнивается по нижнему краю. Его пропорции сохраняются; название на обложке не обрезается. Размер слота резервируется до загрузки, чтобы появление картинки не сдвигало текст.

**Для обеих тем используется один оригинальный файл каждой обложки.** Светлый снимок точнее сохраняет исходные издания; небольшие изменения букв и рисунков в сгенерированной тёмной версии не являются новыми ассетами.

При реализации брать исходные изображения из данных каталога. Не вырезать их из сгенерированного макета при наличии оригиналов и не восстанавливать названия из искажённых пикселей.

Сохранить чёрную обложку Computer Science с белым корешком, тёмную «Сам себе программист», оранжевую книгу Робин Уильямс и зелёный Computer Science с жуком. Тёмная тема не применяет к изображениям `invert`, общую тонировку, уменьшение яркости или прозрачности.

Радиус — 4 px. В тёмной теме мягкий край `--color-cover-edge` помогает различить тёмную книгу на фоне страницы. Тень умеренная; если исходное изображение уже содержит корешок или тень, второй сильный объём не добавляется. Контур следует краю изображения, а не широкому слоту вокруг него.

При отсутствии обложки показывается резервный слот того же размера: фон `--color-surface`, тонкий книжный знак, короткое название. Ошибка изображения переводит карточку в это же состояние. Резервный слот адаптируется к теме, поскольку принадлежит интерфейсу.

Если полное название уже находится внутри той же ссылки, обложка получает пустой `alt`, чтобы не дублировать название. Самостоятельное информативное изображение получает осмысленное описание.

### 9.3. Тематические чипы

Чип содержит маленькую контурную иконку и текст ярлыка. Минимальная высота — 22 px; поля по горизонтали — 8 px; промежуток между иконкой и текстом — 4 px. Иконка — 12 px; радиус — 999 px. Между чипами по горизонтали и вертикали — 6 px.

Все ярлыки используют одну нейтральную палитру `--color-tag-*`. Цвет не кодирует жанр, статус чтения или место хранения. Текст и иконка передают категорию явно.

Длинный ярлык может переноситься внутри чипа; его высота растёт вместе с текстом. Чип не выходит за пределы карточки. Как информационному элементу, ему не требуется искусственно увеличивать высоту до размера кнопки.

## 10. Светлая, тёмная и системная темы

### 10.1. Сохранённый выбор и применённая палитра

Разделять два значения:

- `themePreference`: `system`, `light` или `dark` — сохранённый выбор пользователя.
- `resolvedTheme`: `light` или `dark` — палитра, фактически применённая сейчас.

| Сохранённый выбор | Системное предпочтение | Применённая палитра |
| --- | --- | --- |
| Системная / `system` | Светлое или не определено | `light` |
| Системная / `system` | Тёмное | `dark` |
| Светлая / `light` | Любое | `light` |
| Тёмная / `dark` | Любое | `dark` |

Первый запуск использует `system`. Системное предпочтение определяется через `prefers-color-scheme`; эта возможность учитывает выбор в ОС или браузере. См. [MDN: prefers-color-scheme][mdn-prefers-color-scheme]. При отсутствии поддержки или определённого предпочтения используется светлая палитра.

Явный выбор светлой или тёмной темы имеет приоритет над системным. При возврате к «Системная» сразу применяется актуальное системное предпочтение. Изменение системной настройки обновляет страницу только в режиме `system` и не перезагружает каталог.

### 10.2. Управление темой

**Дополнение к показанным макетам:** внизу боковой панели разместить компактную настройку с видимой подписью «Тема» и полем выбора. Варианты — «Системная», «Светлая», «Тёмная». Высота поля — не менее 44 px; оно использует общие фон, границу, радиус и фокус управления.

При выбранной «Системная» поле продолжает показывать это слово, даже если сейчас применяется тёмная палитра. Состояние обозначает предпочтение пользователя, а не результат его вычисления.

На узком экране настройка находится в выдвижной панели после списка ярлыков. Она не становится четвёртым сегментом сортировки и не занимает место в строке поиска. Если содержимое панели не помещается по высоте, настройка остаётся доступна через прокрутку.

### 10.3. Сохранение и инициализация

Для локального сохранения использовать ключ `my-library.theme` со значением `system`, `light` или `dark`. Выбор сохраняется в данном браузере между посещениями. Синхронизация с аккаунтом и другими устройствами этой спецификацией не предусмотрена.

Перед первым показом каталога применить `resolvedTheme` к `html[data-theme]`; `data-theme-preference` может хранить исходный выбор для интерфейса настройки. Начальная установка темы выполняется без анимации, до отображения содержимого, чтобы не возникала вспышка другой палитры.

Минимальный пример ранней инициализации; он не заменяет обработчики выбора и системных изменений:

```js
(() => {
  const key = "my-library.theme";
  const allowed = new Set(["system", "light", "dark"]);
  let preference = "system";

  try {
    const saved = localStorage.getItem(key);
    if (allowed.has(saved)) preference = saved;
  } catch {
    // Настройка недоступна: используем системное предпочтение.
  }

  const prefersDark = typeof window.matchMedia === "function"
    && window.matchMedia("(prefers-color-scheme: dark)").matches;
  const resolved = preference === "system"
    ? (prefersDark ? "dark" : "light")
    : preference;

  document.documentElement.dataset.theme = resolved;
  document.documentElement.dataset.themePreference = preference;
})();
```

После инициализации приложение обязано обрабатывать следующие события:

| Событие | Действие |
| --- | --- |
| Пользователь выбирает тему | Обновить предпочтение, применить вычисленную палитру, сохранить разрешённое значение |
| ОС или браузер меняет предпочтение | Пересчитать палитру, если текущее предпочтение — `system` |
| Запись настройки недоступна | Применить выбор в текущем сеансе; каталог продолжает работать |
| Сохранено неизвестное значение | Использовать `system`; не применять неизвестное значение как CSS-тему |
| Возврат к каталогу | Восстановить текущую палитру и актуальную подпись настройки |

В приложении с серверной отрисовкой начальное состояние темы и последующая инициализация компонентов должны быть согласованы. Для базового отображения без JavaScript можно использовать те же тёмные токены в `@media (prefers-color-scheme: dark)` для `:root:not([data-theme])`; этот блок генерируется из того же набора цветов и не перекрывает явный выбор.

### 10.4. Что меняется при переключении

Переключение обновляет фоны, текст, границы, тени, фокус, резервные обложки, скелетоны и поверхности раскрытых элементов. Размеры, выбранный ярлык, поисковый запрос, сортировка, порядок подходящих книг, позиция прокрутки и фокус сохраняются.

Обложки не перезагружаются и не получают цветовых фильтров. Нельзя создавать второй каталог или повторно загружать его данные только ради темы.

Палитра меняется сразу. Короткие переходы 150 мс относятся к отдельным hover/focus-состояниям; общая анимация всех свойств страницы через `transition: all` не применяется.

### 11.1. Основное управление

На широком экране поиск и сортировка стоят в одной строке. Если поиск становится уже 280 px или полные подписи перестают помещаться, сортировка переходит ниже поиска.

Ниже 768 px сортировка представлена одним полем выбора с видимой подписью «Сортировка» и теми же тремя вариантами. Это альтернативное представление того же значения: оба варианта управления не должны одновременно попадать в порядок Tab.

Поиск и мобильное поле сортировки занимают доступную ширину и имеют высоту 48 px. Подписи не заменяются непонятными сокращениями. Между строками — 12 px; от управления до книг — 24–32 px.

При скрытой постоянной панели и выбранном ярлыке под управлением показывается компактная строка «Ярлык: Программирование» с действием «Сбросить ярлык». Она сохраняет видимость действующего ограничения после закрытия панели. Название переносится при необходимости; действие имеет область нажатия не менее 44 × 44 px и снимает только ярлык, сохраняя поиск и сортировку. При выборе «Все книги» строка отсутствует. Это адаптивное дополнение использует общие цвета текста, поверхности и фокуса.

На одноколоночном экране текстовый блок карточки ограничен шириной 320 px и центрируется вместе с карточкой в основной области. Текст внутри выравнивается влево; обложка центрируется относительно этого блока. Размер текста остаётся пригодным для чтения.

### 11.2. Мобильная навигация

Ниже 1024 px появляется верхняя строка с кнопкой меню и названием «Моя библиотека». Кнопка меню имеет область нажатия 44 × 44 px и доступное название «Открыть ярлыки».

Выдвижная панель имеет ширину `min(310px, 88vw)` и фон `--color-sidebar`. В ней остаются логотип, все ярлыки со счётчиками и настройка темы. При ширине панели до 288 px применяется компактный логотип и поля из раздела 7.1. Снаружи используется `--color-scrim`.

Панель получает доступное название «Ярлыки библиотеки», отдельную кнопку закрытия, модальный режим и управление фокусом. Пока она открыта, фон недоступен для взаимодействия. Escape, кнопка закрытия и нажатие на затемнённую область закрывают панель и возвращают фокус к инициатору.

Выбор ярлыка применяет фильтр, закрывает панель и переводит фокус в область результатов с доступным названием «Книги», `tabindex="-1"` и видимой обводкой. Постоянно скрытый `h1` не используется как невидимая цель фокуса. Выбор темы сохраняет панель открытой и фокус на поле темы. Прокрутка страницы блокируется только на время модального открытия и корректно восстанавливается при закрытии.

## 12. Загрузка, пустые состояния и ошибки

Все состояния получают цвета из текущей темы. Для них не создаются отдельные светлые подложки поверх тёмной страницы.

| Состояние | Представление | Поведение / действие |
| --- | --- | --- |
| Первая загрузка | Скелетоны обложек и коротких текстовых блоков по текущей сетке | Размеры зарезервированы; неизвестные счётчики обозначены «—», а не нулём |
| Обновление выдачи | Уже показанные книги остаются; рядом с результатами небольшой индикатор | Фокус сохраняется; запоздавшие ответы игнорируются |
| Пустая коллекция | «В библиотеке пока нет книг» и короткое пояснение | Счётчик «Все книги» равен 0; действия добавления определяются отдельным сценарием продукта |
| Нет совпадений | «Книги не найдены» и пояснение про текущий поиск / ярлык | «Очистить поиск» и, при ограничении по ярлыку, «Сбросить поиск и ярлык» |
| Ярлык без записей | «В этом ярлыке пока нет книг» | «Все книги» при пустом запросе; при запросе используется состояние отсутствия совпадений |
| Ошибка первой загрузки | «Не удалось загрузить книги» | Кнопка «Повторить»; ошибка не выглядит пустой библиотекой |
| Ошибка обновления | Сохраняется последняя успешная выдача; «Не удалось обновить результаты» | «Повторить»; прежние результаты явно обозначены как не обновлённые |
| Нет обложки или ошибка картинки | Резервный слот того же размера | Название, автор и ярлыки доступны |
| Автор не указан | «Автор не указан» цветом `--color-muted` | Карточка сохраняет структуру |
| Ярлыки не назначены | Строка чипов отсутствует | Книга остаётся доступна в «Все книги» и поиске |

«Очистить поиск» оставляет ярлык. «Сбросить поиск и ярлык» очищает оба ограничения, сохраняя сортировку. При действительно пустой коллекции не показывать сообщение о неудачном поиске как основной диагноз.

Подтверждения и число результатов объявляются через спокойную область уведомлений. Индикатор загрузки не захватывает фокус. Для скелетонов достаточно ровной подложки; пульсация необязательна и отключается при `prefers-reduced-motion`.

## 13. Иконки, доступность и контраст

### 13.1. Общие правила

Использовать один согласованный набор контурных SVG-иконок. Основной размер — 16–20 px, у меню и поиска — 20 px, у книжного знака — 32 px, у чипа — 12 px. Толщина линий около 1,5–1,75 px, с оптической корректировкой для маленького размера. Emoji не заменяют иконки управления.

Язык страницы — `lang="ru"`. Используются семантические области навигации, поиска и основного содержимого, один `h1` и список карточек. Предусмотреть ссылку «Перейти к книгам», видимую при фокусе. Она переносит фокус в область результатов с `tabindex="-1"` и видимой обводкой; область не добавляет лишнюю остановку в обычном порядке Tab.

Все действия доступны с клавиатуры. Иконки рядом с понятной подписью декоративные; элементы без видимого текста получают доступные названия. Поля темы и сортировки имеют связанные подписи. Пустое поле поиска сохраняет доступное имя после исчезновения placeholder.

Фокус обозначается контуром **3 px** с отступом **3 px**. Цвет — `--color-focus`. Между контуром и выбранным зелёным элементом сохраняется полоса окружающего фона, чтобы фокус был различим независимо от заливки. Обводка не обрезается контейнером и не меняет размеры компонента.

У скруглённого выбранного элемента в pressed-состоянии добавляется внутренний контур `--color-on-primary`; он сохраняет различимую границу на более тёмной нажатой заливке. Фокус и выбор остаются разными состояниями.

Проектный минимум области нажатия основных действий — **44 × 44 CSS px**. Информационные чипы не являются маленькими кнопками. Порог WCAG 2.2 AA в критерии 2.5.8 — 24 × 24 CSS px с оговорёнными исключениями; 44 px здесь — сознательный запас удобства. См. [W3C: Target Size Minimum][wcag-target].

Панели и меню не скрывают активный фокус. При увеличении текста до 200% и на ширине 320 CSS px сведения и действия остаются доступными без горизонтальной прокрутки всей страницы. При `prefers-reduced-motion` убираются перемещение панели и декоративная пульсация; функциональные изменения происходят сразу.

### 13.2. Численные требования

Для обычного текста принимается контраст не менее **4,5:1**. WCAG допускает 3:1 для крупного текста; в этой системе основные заголовки имеют больший запас. См. [W3C: Contrast Minimum][wcag-contrast].

Для необходимых границ управления и визуальных индикаторов состояния принимается не менее **3:1** относительно соседней поверхности. Мягкая декоративная линия не заменяет такую границу. См. [W3C: Non-text Contrast][wcag-non-text].

Расчёт ниже выполнен для непрозрачных sRGB-цветов таблицы 5.1, без текстуры, наложенных слоёв и эффектов. Значения округлены для показа; прохождение порога проверяется по неокруглённому числу.

| Сочетание | Светлая | Тёмная | Минимум в проекте |
| --- | ---: | ---: | ---: |
| Основной текст / страница | 10.82:1 | 13.96:1 | 4.5:1 |
| Вторичный текст / страница | 4.98:1 | 8.43:1 | 4.5:1 |
| Подсказка / поле поиска | 4.69:1 | 6.92:1 | 4.5:1 |
| Подпись / выбранный зелёный | 7.72:1 | 4.70:1 | 4.5:1 |
| Подпись / зелёный при наведении | 8.95:1 | 4.56:1 | 4.5:1 |
| Текст ярлыка / его подложка | 8.61:1 | 8.67:1 | 4.5:1 |
| Ошибка / её подложка | 5.28:1 | 7.38:1 | 4.5:1 |
| Граница поля / поверхность поля | 3.46:1 | 3.85:1 | 3:1 |
| Выбранный сегмент / поверхность сортировки | 7.64:1 | 3.11:1 | 3:1 |
| Выбранный пункт / боковая панель | 7.00:1 | 3.19:1 | 3:1 |
| Фокус / фон страницы | 6.52:1 | 10.56:1 | 3:1 |

Эти расчёты подтверждают указанные цветовые пары, но не означают, что рабочий сайт уже проверен на соответствие WCAG. При реализации отдельно оцениваются фокус, клавиатура, тексты, увеличение, реальные изображения и все состояния компонентов.

## 15. Критерии готовности реализации

### Визуальная система

- [ ] На большом экране совпадают состав панели ярлыков, порядок управления и четыре колонки каталога.
- [ ] При одинаковой ширине окна смена темы не изменяет геометрию, переносы текста, порядок книг и положение прокрутки.
- [ ] Все цвета компонентов получены из семантических токенов; оба набора содержат одинаковые роли.
- [ ] Поиск, сортировка, настройка темы, состояния загрузки и ошибки оформлены в обеих темах.
- [ ] У карточки нет общей фоновой панели; обложки имеют единые слоты и исходные пропорции.
- [ ] В обеих темах используются одни оригинальные файлы обложек без инверсии и затемнения.
- [ ] Тёмные обложки различимы на фоне; текст и необходимые границы соответствуют требованиям контраста.
- [ ] Кириллица, «Ёё», латиница, цифры и длинные смешанные названия корректно отображаются выбранными шрифтами.

### Поведение

- [ ] Поиск работает по названию, автору и имеющемуся ISBN; нормализация ISBN не ломает текстовый поиск.
- [ ] Поиск и один выбранный ярлык образуют согласованное пересечение; «Все книги» снимает только ярлык.
- [ ] Очистка поля и общий сброс имеют разные, явно описанные действия.
- [ ] Сортировка использует три указанных варианта и устойчивый порядок при равных значениях.
- [ ] Счётчики получены из данных всей коллекции; отсутствие данных не выдаётся за ноль.
- [ ] Первичная ошибка, ошибка обновления, пустая коллекция и отсутствие совпадений различаются.
- [ ] Смена темы не вызывает повторную загрузку книг и не сбрасывает поиск или фокус.

### Тема и доступность

- [ ] Проверены первый запуск, явный выбор light/dark, возврат к system и изменение системного предпочтения.
- [ ] Сохранённая настройка восстанавливается; неизвестное значение и отказ хранилища не ломают каталог.
- [ ] До первого отображения применяется правильная палитра; `color-scheme` согласован с ней.
- [ ] Выбранное «Системная» остаётся выбранным при фактически светлой и тёмной палитре.
- [ ] Навигация, сортировка, поиск и выбор темы доступны с клавиатуры; фокус виден в обеих темах.
- [ ] Выдвижная панель управляет фокусом, закрывается по Escape и корректно возвращает фокус.
- [ ] При закрытой мобильной панели выбранный ярлык виден в основной области; после выбора фокус имеет видимое положение.
- [ ] На ширинах 320, 480, 768, 1024, 1280, 1600 и 1885 CSS px нет перекрытий и горизонтального скролла страницы.
- [ ] Увеличение текста до 200%, длинные имена, отсутствие обложки и reduced motion обработаны.

Это перечень приёмки будущей реализации. Чекбоксы намеренно оставлены незаполненными: данный запрос обновляет спецификацию, а не код сайта.
